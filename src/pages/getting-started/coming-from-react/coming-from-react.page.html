MThemeProvider → provideMineralUI(), MI18nProvider → provideMineralI18n(), MToastProvider → the optional provideMineralToast(). The theme class and token overrides go on <html>. Every component has its own entry point (@banzamel/mineralui-angular/controls/button); groups and the root re-export them. See Installation.

Add @banzamel/mineralui-angular/styles.css to styles in angular.json. Every class has the m- prefix (.button.outlined → .m-button.m-outlined, utilities such as .m-mt-md), keyframes too. The --mineral-* tokens and .theme-light / .theme-dark are unchanged, so theme files work for both frameworks.

As in React 2.5.3+, all framework CSS sits in the cascade layer mineral, so your overrides need no extra specificity. React injects its style tag first in <head>; in Angular the order comes from angular.json — keep the library's styles.css first in styles (Installation).

component, as, href and to are gone: button[mButton], a[mButton], a[mLink], a[mCard]. Semantic tags carry what level and ordered did (h1[mHeading]…h6[mHeading], ul[mList] / ol[mList]). The library does not depend on @angular/router — put your routerLink on the host. Composite components are elements: <m-card>, <m-stack>, <m-date-picker>.

[(value)], [(open)], [(page)] — bind a signal or leave the model alone. Callbacks are outputs ((closed), (itemClick), (action)), and data items hold no functions: an output emits the item. Inputs never reuse global HTML attribute names: title on modals and sheets is heading, on icons and illustrations label.

Use formControlName, [formControl], ngModel or [formField]. MValidators adapt the React validation rules to ValidatorFn, MRules to Signal Forms schemas; the React ValidatorFn type is MValueValidator. Specialized inputs validate for real, and their models hold raw values (phone digits, number | null, Date | null). Date bounds are minDate / maxDate. See Form and Signal Forms.

startIcon / endIcon, headers and addons are slot attributes: mStart, mEnd, mPrepend / mAppend in MInputGroup. One <m-icon [icon]> renders V1 and V2 icons; V2 constants are in icons/v2 (Pro) and there is no MIconV2 icon="name" registry. Illustrations: <m-illustration [illustration]>. See Icons.

mCell, mRowDetail, mSelectOption, mPopoverContent. Data hooks useMTable / useMCardGrid become injectMDataSource(fetcher) / externalMDataSource() passed as [source], with {items, total} responses. See DataTable.

hidden="md" → hiddenUpTo="md" (with hiddenAbove unchanged); spacing props (mt, px, spacing…) come from MSpacing. useMaxWidth → injectMaxWidth(breakpoint), a Signal<boolean>. See Responsive Hidden.

Services expose signals (mode, resolvedMode, locale, dict); templates translate with the mT pipe. A scoped theme (scope="wrapper") is the [mTheme] directive, not persisted by default. mineralui.* keys are the same as in React; texts hard-coded in React have new keys and overriding inputs. See Theming, Languages (i18n) and Toast.

  • useClickOutside → (mClickOutside), useKeyboardNav → [mKeyboardNav] + mKeyboardNavItem, useGhostText → [mGhostText], ripple → [mClickEffect], reveal → [mReveal].
  • Removed: useDebounce* (use RxJS or signals), cn (class bindings), useControllableString (model()).

Modals, drawers and sheets are a native <dialog> opened with showModal(); popovers, dropdowns, tooltips and pickers use popover="manual". A toast shown from a modal stays above it. MPortal stays as a primitive for your own content — see Primitives.

  • Select and autocomplete are APG comboboxes.
  • Date pickers are APG date picker dialogs with grid keyboard navigation.
  • Sortable tables use aria-sort and header buttons.
  • Dialogs restore focus and make the page behind them inert.
  • Toasts use two live regions; the timer pauses on hover and focus.
